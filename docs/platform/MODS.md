# 在 Matcha 中管理 VPK Mod

打开 **Mod** 页面。Matcha 扫描所选游戏的 `left4dead2/addons/*.vpk`、`addons/workshop/*.vpk` 和 `.matcha-library/workshop/` 独立库，读取包内 `addoninfo.txt`，显示名称、作者、版本、大小、资源数量和目录。

`addonlist.txt` 支持 UTF-8、带 BOM 的 UTF-16LE，以及中文 Windows 常见的 GBK/GB18030 编码；导入和应用方案时沿用原编码，保留已有启停项、注释与顺序。

## 导入并启用

1. 把现成的 VPK 拖到 **Mod** 页，也可点 **添加 → 本地 VPK 文件…**。分卷包选择 `_dir.vpk`，相关分卷放在来源文件旁。
2. 检查来源、体积和目标目录，再确认导入。首次导入或手动替换同名 VPK、素材文件夹，都会在当前启动方案中启用，下次启动游戏时生效。来源文件保留，替换前会备份旧 VPK 和分卷。工坊更新沿用原开关。
3. 用列表里的开关选择要启用的 Mod。页头最右侧如果显示 **设为启动方案**，点它。
4. 回主页用 **L4N 平台** 启动游戏。Matcha 会先把启动方案的启停状态写入 `addonlist.txt`，修改前将原配置备份到 `left4dead2/.matcha-backups/`。

游戏运行期间可扫描、编辑草稿；导入和应用在游戏退出后执行。写入前再次检查进程与文件变化。工坊文件内容保持原样，启停由 `addonlist.txt` 管理。

### 从桌面文件夹打包

在 **Mod** 页打开目标分类，把桌面上的素材文件夹拖进来，点 **打包并导入**。例如 `海风涂装/materials/…` 会生成 `海风涂装.vpk`，包内从 `materials/…` 开始。单独拖入 `materials`、`models` 或 `sound` 等游戏资源目录时，会保留这一级目录名。

也可以点 **添加 → 打包素材文件夹…**，或一次拖进多个文件夹和 VPK。每个素材文件夹各生成一个包；已有的 `addoninfo.txt` 原样收录，缺少时用文件夹名在包内补一份。原目录保持原样，成品进入选中的分类并保持停用。大文件夹在后台处理，可在 **下载** 页查看进度或取消。

## 在内置创意工坊找 Mod

1. 点左侧导航的 **创意工坊**（罗盘图标）。搜索关键词，按地图、人物、武器、声音等分类浏览；排序支持本周热门、最新发布、最近更新、最多订阅。
2. 点击预览图或标题查看介绍、作者、大小与更新时间。切换 **合集** 可浏览合集，并通过 **选择合集内容** 勾选需要的作品。
3. 点击 **下载**，底部任务栏显示进度、取消和重试。完成后点右上角 **新下载** 整理，再手动加入方案。
4. 已有链接时，点 **粘贴链接**；搜索框也可直接提交工坊链接或条目 ID。

浏览使用 Steam 公开页面，详情与下载沿用官方接口和 CDN。尚无官方直链的作品提供 **在 Steam 查看**。联网沿用环境代理或 Windows 当前启用的手动系统代理；连接失败时可调整网络后点 **重新加载**。列表短暂缓存两分钟，缩略图按需加载。

工坊下载会把静态封面保存到独立库条目旁的 `mod.jpg`，后续离线读取。独立库、Steam 订阅目录和以数字工坊 ID 命名的本地导入 VPK，在卡片首次显示时按需补图；数字文件名先经 Steam 接口核实为 L4D2 条目，再获取封面。本地条目缓存为同名 `.jpg`，已有封面和原 VPK 保持原样。封面获取失败时保留已下载的 Mod；网络恢复后重新进入 Mod 页即可重试补图。

## 从 B站、爱发电或作者网页下载

1. 点左侧 **浏览器**（地球图标），首页选择 B站、爱发电或 Steam，也可在地址栏粘贴作者链接。
2. 标签页支持前进、后退、刷新和收藏；按游戏目录保存标签。登录状态保存在 Matcha 独立的网页资料目录。原站的登录、验证码、赞助与购买由用户操作；网页需要外部应用时，可点右上角 **在系统浏览器打开**。
3. 文件下载后点右上角 **下载**。VPK 点击 **导入**；ZIP 点击 **选择内容**，勾选 VPK 后导入，分卷一起提取。RAR、7z 和加密包在文件夹中解压后，通过原有本地 VPK 导入入口处理。
4. 导入后到 Mod 页 **新下载** 查看。详情里的 **来源** 可回到识别出的作者页，**下载页** 可回到实际取文件的页面。让茶茶导入同一条网页下载也会保留这些来源。新 Mod 默认加入当前启动方案，下次启动生效；游戏运行时可继续下载，退出游戏后再导入。

下载完成的卡片上，点 B站的 **直接点赞** 会用内置浏览器里的账号给原视频点一个赞，不投币、不收藏。若提示登录，登录后会回到原视频，在那里点一下赞即可。

在 **设置 › 存储** 查看下载位置。ZIP 内的 Mod 全部导入后，默认清理原包，下载记录和来源页保留。只选了部分 Mod、导入失败或关闭自动清理时，原包继续保留。中断下载显示中断状态，可返回原页面重试。ZIP 导入上限为 4096 个条目、VPK 解压总量 8 GiB；超出时先在文件夹中整理后导入。

内置浏览器复用 [DSH Browser 0.4.1](https://github.com/Nono-neko/dsh-browser) 的标签状态、恢复和地址解析，采用原生 WebView2 承载网页。右侧 Pi 助手保持原有能力。

网页下载通过 WebView2 的原生下载对象上报已收字节和总字节，进度事件最多每 200 ms 一次，完成或失败时立即发送最后状态。总大小未知时保持未定进度，下载页继续显示已收大小和实时速度。任务栏与侧栏显示统一的下载进度，全部结束后清除任务栏进度。

## 快速实测：使用自己的地图 MOD

1. 先将测试地图 VPK 导入 MOD 库，或通过工坊链接下载。
2. 点击 **快速实测**。选中列表中的 MOD 后打开，会带入当前选择；右键 MOD 也可打开。
3. 指定 **地图 MOD** 和其中的地图 / 章节。地图包自动加入本次加载，额外依赖包在左侧勾选。
4. 点击 **开始测试**。Steam 保持登录，游戏以无边框小窗直接进入地图；窗口默认 960×540。

测试内容由所选地图和 MOD 决定，人物、模型、材质、声音等 MOD 均按选择加载；装备由地图和玩家自行安排。停止刷怪和无限弹药默认开启，可按需关闭。F7 / F8 切换第三 / 第一人称，F10 退出测试；退出地图时也会直接退出本次测试游戏。退出后可更换 MOD 并点击 **再次测试**。每次开始时记住地图、MOD 和窗口设置。

测试目录位于所选游戏根目录的 `.matcha-tests/<环境 ID>/`。新版从该目录下的游戏程序启动，工作目录、默认游戏目录和配置一起隔离；所选 VPK 按勾选顺序排列，随后加载地图包和基础资源。原方案与 `addonlist.txt` 保留，启动走 D3D9 本地开发模式。

相同 MOD 组合复用环境和游戏产生的缓存；改变窗口或同一地图包内的章节继续复用。来源文件更新、替换或缓存链接缺失时重新准备，旧环境与日志保留。启动阶段只读取所选 VPK，省去再次扫描整个库；大资源使用同盘链接，声音缓存和配置独立保存。面板显示缓存是否命中及环境准备耗时，玩家进场后固定显示本次进场用时。

日志入口位于面板下方，主要日志为环境中的 `flare/console.log`，同时读取默认游戏目录、`bin/` 和环境根目录的日志。每次启动生成独立配置与进场标记，避免上次日志误报成功。资源校验拒绝进场时直接显示失败原因；等待超过 45 秒时，会区分配置尚未收到回执或玩家仍在加载。

游戏运行期间，启动下一次测试和部署 MOD 的操作会等待用户退出游戏。离线夹具覆盖独立程序与工作目录、资源优先级、分卷包、缓存复用及失效、旧日志过滤、资源根路径、配置保留、运行中拦截与失败恢复。

`-insecure` / VAC 安全模式已禁用是本地开发模式的提示。2026-11-16 的环境 v3 实机日志已确认独立配置载入和玩家进场，进场约用 17.5 秒。本次更新移除装备发放、装备选择与 F6 取枪，并为进场回执加入单次执行保护；复用旧环境时清理 Matcha 原来生成的 F6 取枪绑定。离线脚本检查已覆盖重复回调、零装备指令和退出事件只提交一次退出指令；退出地图后的实际关窗行为及 MOD 外观由用户下次实测确认。

## 看懂草稿与游戏配置

- 卡片开关编辑当前方案；Mod 详情中的游戏启停状态读取 `addonlist.txt`。
- “未登记”表示该 addons VPK 尚无配置条目；首次草稿默认选中可解析的 addons 新 VPK。Matcha 独立库新下载保持停用，等待手动加入方案。
- 需要手动操作时，右键左侧的方案名。**从游戏同步** 用游戏当前设置覆盖该方案的 Mod 勾选；**应用到游戏** 提前写入游戏设置，同时将它设为启动方案。
- VPK 方案与 DLL 的 `enabled.txt` 分开管理。桌面「L4N 平台启动」沿用当前方案，基础参数为 `-steam -novid`；「纯净对抗」使用经过检查的 Steam 原版目录。

## 处理资源重叠

冲突检测比较规范化的包内资源路径（大小写与斜杠统一），排除 `addoninfo.txt` 和附加包封面。展开条目查看与其他 Mod 重叠的路径；每对最多显示 200 条，完整数量单独标注。

重叠项由游戏的实际加载顺序处理。可以在方案中停用其中一个 Mod，再使用该方案启动。解析失败的包单独显示错误，其他包继续扫描。

## 恢复一次应用

退出游戏后，从 `.matcha-backups` 选择对应时间的 `addonlist-*.txt`，先保存当前 `addonlist.txt` 副本，再将选定备份复制为 `left4dead2/addonlist.txt`。平台会保留每次修改前的原始内容、注释、未知条目与编码。

## Pi 工具

`mod_inventory` 只读扫描；`mod_set_enabled` 修改指定条目；`mod_import` 导入文件。后两者需要界面确认并检查游戏进程。Pi 直接修改游戏配置后，可在 Mod 页重新扫描，再右键方案名选择 **从游戏同步**。

## 实现与检查

`backend/mods/` 是桌面与 Pi 共用的模块。VPK v1/v2 支持目录树、预载字节、内嵌数据和外部分卷；扫描只读取元数据，解包和声音预览按需读取资源。缓存按文件大小、修改时间和文件身份失效。格式实现参考 [ValvePython VPK reader](https://github.com/ValvePython/vpk)。

桌面解包、声音预览、工坊链接下载及内置工坊浏览页已接入，详见 [接入契约](../mod-library-plan.md)。独立库下载完成后保留源文件；启用时在 addons 建立硬链接，停用只移除链接。文件系统不支持硬链接时才复制；旧版的相同副本可在 **设置 › 存储** 转为硬链接。遇到同名或外部修改的部署文件时先保留文件，再提示处理。开发声音辅助程序使用 `npm run audio:build`；桌面构建自动包含此步骤。

`node --test backend/tests/mods.test.mjs` 检查解析、缺失分卷、重叠资源、导入登记为停用、文件保留、备份、进程锁定和桌面方案应用。真实游戏目录完成只读扫描；VPK 导入与启停写入在隔离夹具中验证，游戏内效果由用户下次启动确认。
