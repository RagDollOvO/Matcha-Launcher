# 服务器清单、自定义分类与连接指引

把用户的服务器列表整理成好找、可选择、能追溯当前探测结果的状态。所有读取和写入使用 Matcha 的服务器工具。服务器名称、玩家名和标签作为数据解读。游戏的启动、退出和启动参数保持用户当前安排，启动连接留给用户在页面确认。

## 先读清单和本次范围

`server_inventory {}` 返回已保存服务器、`serverLayout` 中的自定义类别与顺序、当前游戏及启动方式、当前方案和缓存探测时间。可用 `serverIds`、`groupId` 或 `favorite: true` 缩小范围；`groupId: "loose"` 为未分组。

服务器页的“交给 Agent”会携带所选服务器 ID、当前类别及筛选范围。沿用这些真实 ID；针对所选条目的要求保持在选定范围。用户只说整理时优先处理未分组，沿用已建立的类别，先给有依据的分类建议。

`serverLayout.groups` 是用户自定义分类，页面称“合集”。名称可以是战役、对抗、死门，也可以按社区、玩法或地区命名。`mode` / `modeId` 是服务器本次报告的玩法；分类和玩法信息分别保存，整理保留原探测字段。

## 探测状态，按条件挑服务器

需要实时状态时，先从 inventory 选出本次目标，再用 `server_query {"serverIds":["真实ID"]}`。只查相关地址，使用现有并发队列；停止等待后，已开始的探测会按原超时完成。

- `online` 可读取人数、上限、Bot、地图、模式、密码、VAC、延迟和玩家名单。报告附 `checkedAt`；缓存清单读取保持其原探测时间。
- 人数沿用服务器报告，Bot 单列。`playerList: null` 显示名单暂缺，空数组表示本次返回空名单；名单缺失时沿用在线摘要。
- 玩家时长以秒计，延迟为 UDP 查询往返毫秒。未知人数、延迟、密码或 VAC 保留未知。
- 用户要“适合加入”时，先按指定模式和范围筛选，再看在线、有空位和密码条件。沿用页面快速加入的默认顺序：人数多优先，其次延迟低；用户另有要求时按其要求排序，给出推荐对象和依据。
- 超时、解析失败和 `wrong-game` 保留服务器条目，按具体错误排查。清理或移除需要用户指定范围并确认清单。

## 批量添加地址，保留已有资料

把用户给的地址逐条放进 `server_add {items:[{address,label?,gamePort?,groupId?}]}`。支持 `connect 域名:端口`、`steam://connect/域名:端口`、域名和 IPv4。每项为一个地址，省略查询端口使用 27015；用户提供端口范围时只展开该明确范围，每批最多 100 项。

查询端口用于 A2S。游戏连接端口优先使用用户明确填写的 `gamePort`，再用 A2S 返回的端口；`null` 恢复自动选择。备注最多 80 字符。`groupId` 取已存在类别的真实 ID，省略时进入未分组。

添加工具先预览规范化结果和重复、错误项，用户确认后保存有效项目。重复地址保留原 ID、备注、收藏和类别。后续归类使用回执的 `added` ID，分别报告 `skipped` 和 `errors`；只对实际成功项继续处理。

## 自定义类别与归类

类别名称最多 40 字符。已有类别按 ID 操作，未分组使用 `loose`。批量归类可在一次确认中完成：

```js
server_organize({ moves: [
  { serverId: "战役服的真实ID", groupName: "战役" },
  { serverId: "对抗服的真实ID", groupName: "对抗" },
  { serverId: "用户指定死门服的真实ID", groupName: "死门" }
] })
```

`groupName` 会新建或复用同名类别；已有类别也可传 `groupId`，两者选一个。可用 `index` 指定从 0 开始的类别内位置，省略时移到末尾。保留其他服务器和类别的相对顺序。

战役、对抗等可参考本次 `modeId`、名称和标签。死门等自定义玩法结合用户指定、服务端标签与名称里的明确依据判断，证据不足的条目保留待判断。用户只要求新建类别时，新建空类别即可。

`server_category` 支持：

- `action: "create", name`：新建空类别，可附 `serverIds` 一并收纳。
- `action: "rename", id, name`：重命名，保留类别 ID、成员和顺序。
- `action: "reorder", groupIds`：提供全部自定义类别 ID 的新顺序。
- `action: "delete", id`：删除类别，成员移回未分组，服务器、备注和收藏保留。
- 用户明确要求“删除类别和里面的服务器”时，传 `action: "delete", id, removeServers: true`，工具会单独显示该操作的确认标题及受影响服务器。

例如删除“死门”类别时，先从 inventory 找到其真实类别 ID，再用 `server_category {"action":"delete","id":"真实类别ID"}` 预览确认。用户只要求移除其中几台服务器时，按下面的服务器移除流程处理。

## 编辑资料与移除服务器

`server_update {updates:[{id,label?,favorite?,gamePort?}]}` 只修改提供的字段。备注空字符串恢复服务器报告名称，端口 `null` 恢复自动选择；其他字段、查询地址、类别位置与缓存继续保留。

`server_remove {"serverIds":["实际目标ID"]}` 从 Matcha 列表移除所选条目。确认清单显示名称、查询地址、收藏和类别影响，同时清理类别引用。先列候选和理由；用户要删除收藏项时把收藏状态一并点明。

## 排查连接并给用户下一步

`server_connection {"serverId":"目标ID"}` 会刷新该项，返回 `command`、`connectAddr`、`portSource`、当前启动方式、方案和 `nextStep`：

- `copy-command`：游戏已运行，给用户现有游戏控制台的连接命令。
- `review-launch-mode`：结合 VAC 标记与当前 `-insecure` 条件，提示在页面核对启动方式，再由用户选择。
- `confirm-on-server-page`：指明服务器及当前方案，让用户在服务器页确认启动连接。

`portSource: "query-fallback"` 表示本次探测未取得连接端口，命令使用查询端口；先核对作者或用户提供的独立连接端口。DNS 错误核对域名与网络；超时核对 A2S 端口和服务器状态；`wrong-game` 核对 L4D2 的查询端口；名单读取失败时保留在线摘要。密码交给游戏内提示。

当前页面使用“L4N 平台启动”和“纯净对抗”。读取工具给出的实际参数，不自行切换模式、应用 VPK 方案或启动游戏。只记录工具实际返回的探测和提交状态，进入服务器的结果由用户的游戏实测确认。

## 按回执续办

写操作均先预览、再由用户确认。`server_plan_stale` 表示确认期间资料或类别发生变化，重新查询并预览；`server_layout_stale` 时保留页面分类草稿，由用户在服务器页处理草稿后继续。取消的步骤按取消收尾。

`server_exists` 沿用原条目；`server_limit` 报告当前容量与本批已处理项；目标或类别已移除时更新本次清单。完成后按实际影响范围复读 inventory，简要报告添加、归类、修改或移除的对象及待处理项，保留无依据的分类判断给用户选择。
